# Документация SQL-объектов приложения Nova Forma CRM

---

## I. Функции бизнес-логики

### 1. Функция `sp_login(p_login VARCHAR, p_password VARCHAR)`
Функция выполняет аутентификацию пользователя. Входные параметры: `p_login VARCHAR` — логин, `p_password VARCHAR` — пароль. Логика: функция ищет запись в таблице `Сотрудник`, где совпадают логин и пароль, возвращая id сотрудника, роль и ФИО. Если сотрудник уволен (`дата_увольнения IS NOT NULL`), возвращается ошибка. Результат: строка со статусом ('OK'/'ERROR'), сообщением, id сотрудника, ролью и ФИО.

### 2. Функция `sp_create_order(p_client_id INTEGER, p_manager_id INTEGER, p_deadline DATE)`
Функция создаёт новый заказ. Входные параметры: `p_client_id INTEGER` — id клиента, `p_manager_id INTEGER` — id менеджера, `p_deadline DATE` — дата готовности. Логика: функция вставляет новую запись в таблицу `Заказ` с указанными параметрами, статусом 'принят' и текущей датой. Результат: строка со статусом ('OK'/'ERROR'), сообщением и id созданного заказа.

### 3. Функция `sp_add_product_to_order_smart(p_order_id INTEGER, p_product_id INTEGER, p_qty INTEGER, p_deadline DATE)`
Функция добавляет изделие в состав заказа, резервирует складские остатки или создаёт задания на производство при нехватке. Входные параметры: `p_order_id INTEGER` — id заказа, `p_product_id INTEGER` — id изделия, `p_qty INTEGER` — количество, `p_deadline DATE` — дата готовности. Логика: функция получает цену изделия, добавляет запись в `СоставЗаказа` с фиксированной ценой. Далее для каждой заготовки из `СоставИзделия` рассчитывается необходимое количество. Если на складе хватает заготовок — уменьшает `количество_готовых` в таблице `Заготовка`. Если не хватает — забирает остаток со склада, рассчитывает недостающее количество, проверяет наличие материалов (без списания), и создаёт запись в `ПланЗаготовок` со статусом 'принято' и `материалы_списаны = FALSE`. При нехватке материалов возвращает ошибку 'НЕОБХОДИМА ЗАКУПКА'. Результат: строка со статусом — 'OK: Изделие добавлено. Все компоненты взяты со склада.' при резервации или 'OK: Созданы задачи для N компонентов.' при создании заданий на производство.

### 4. Функция `sp_add_order_item(p_order_id INTEGER, p_product_id INTEGER, p_qty INTEGER)`
Функция добавляет изделие в заказ через диалог создания заказа. Входные параметры: `p_order_id INTEGER` — id заказа, `p_product_id INTEGER` — id изделия, `p_qty INTEGER` — количество. Логика: аналогична `sp_add_product_to_order_smart`, но дата готовности берётся из заказа (`дата_готовности`). Перед внесением изменений проверяет, что заказ не завершён/отменён. Проверяет наличие материалов. Списывает заготовки со склада, создаёт задачи в `ПланЗаготовок` при недостаче с учётом уже существующих невыполненных задач. Результат: строка со статусом ('OK'/'ERROR') и сообщением.

### 5. Функция `sp_update_order_status(p_order_id INTEGER, p_new_status VARCHAR)`
Функция обновляет статус заказа с бизнес-логикой отмены. Входные параметры: `p_order_id INTEGER` — id заказа, `p_new_status VARCHAR` — новый статус. Логика: проверяет текущий статус заказа. Запрещает изменение отгруженных и уже отменённых заказов. При завершении (`'завершен'`) проверяет, что все задачи в `ПланЗаготовок` выполнены. При установке статуса `'в_работе'` из `'завершен'` — фиксирует брак. При **отмене** (`'отменен'`): 1) для каждой незавершённой задачи, где `материалы_списаны = TRUE`, возвращает материалы на склад; 2) для выполненных задач возвращает произведённые заготовки на склад; 3) отменяет все задачи; 4) возвращает заготовки, взятые со склада при создании заказа. Результат: строка со статусом ('OK'/'ERROR') и сообщением.

### 6. Функция `sp_create_manual_production_task(p_order_id INTEGER, p_component_id INTEGER, p_qty INTEGER, p_deadline DATE DEFAULT NULL)`
Функция создаёт ручную задачу на производство заготовки. Входные параметры: `p_order_id INTEGER` — id заказа, `p_component_id INTEGER` — id заготовки, `p_qty INTEGER` — количество, `p_deadline DATE` — дедлайн (по умолчанию берётся из заказа). Логика: проверяет наличие материалов (без списания). Если материалов недостаточно — возвращает ошибку с перечислением недостающих. Если задача для данной заготовки/заказа уже существует и не завершена, увеличивает `плановое_количество`. Иначе — создаёт новую запись в `ПланЗаготовок` со статусом 'принято' и `материалы_списаны = FALSE`. Результат: строка со статусом ('OK'/'ERROR') и сообщением.

### 7. Функция `sp_take_component_task(p_component_id INTEGER, p_order_id INTEGER, p_worker_id INTEGER)`
Функция позволяет сотруднику взять задачу в работу. Входные параметры: `p_component_id INTEGER` — id заготовки, `p_order_id INTEGER` — id заказа, `p_worker_id INTEGER` — id сотрудника. Логика: проверяет, что сотрудник не уволен (`дата_увольнения IS NOT NULL`). Проверяет, что задача существует, не выполнена и не занята другим. **Списывает материалы** со склада (если ещё не списаны): для каждого материала из `РасходМатериалов` уменьшает `количество_на_складе` на `количество_материала * плановое_количество`. При нехватке материалов — возвращает ошибку. Устанавливает `статус = 'в_работе'`, `материалы_списаны = TRUE`. Результат: строка со статусом ('OK'/'ERROR') и сообщением.

### 8. Функция `sp_submit_component_work(p_component_id INTEGER, p_order_id INTEGER, p_qty INTEGER, p_worker_id INTEGER)`
Функция обрабатывает сдачу выполненной работы. Входные параметры: `p_component_id INTEGER` — id заготовки, `p_order_id INTEGER` — id заказа, `p_qty INTEGER` — сданное количество, `p_worker_id INTEGER` — id сотрудника. Логика: проверяет, что задача существует, назначена этому сотруднику и не завершена. Проверяет, что сумма фактического и сдаваемого количества не превышает плановое. Увеличивает `фактическое_количество`, устанавливает `дата_факт = CURRENT_DATE`. Если факт >= план — статус меняется на 'выполнено'. Для **служебных заказов** (без клиента) — увеличивает `количество_готовых` в таблице `Заготовка` (пополнение склада). Результат: строка со статусом ('OK'/'ERROR') и сообщением 'Работа принята'.

### 9. Функция `sp_release_task(p_id_заготовки INTEGER, p_id_заказа INTEGER)`
Функция снимает задачу, возвращая материалы. Входные параметры: `p_id_заготовки INTEGER` — id заготовки, `p_id_заказа INTEGER` — id заказа. Логика: проверяет, что задача существует и не выполнена. Если `материалы_списаны = TRUE`, рассчитывает количество для возврата (`плановое - фактическое`) и для каждого материала из `РасходМатериалов` увеличивает `количество_на_складе`. Сбрасывает задачу: `id_сотрудника = NULL`, `статус = 'принято'`, `фактическое_количество = 0`, `материалы_списаны = FALSE`. Результат: строка со статусом ('OK'/'ERROR') и сообщением.

### 10. Функция `sp_assign_worker_to_task(p_id_заготовки INTEGER, p_id_заказа INTEGER, p_worker_id INTEGER)`
Функция назначает сборщика на задачу. Входные параметры: `p_id_заготовки INTEGER` — id заготовки, `p_id_заказа INTEGER` — id заказа, `p_worker_id INTEGER` — id сотрудника. Логика: проверяет, что сотрудник не уволен. Обновляет `id_сотрудника` и `статус = 'назначено'` в `ПланЗаготовок`. Результат: строка со статусом ('OK'/'ERROR') и сообщением.

### 11. Функция `sp_report_defect(p_order_id INTEGER, p_product_id INTEGER, p_qty INTEGER, p_reason VARCHAR)`
Функция фиксирует брак по изделию. Входные параметры: `p_order_id INTEGER` — id заказа, `p_product_id INTEGER` — id изделия, `p_qty INTEGER` — количество бракованных, `p_reason VARCHAR` — причина. Логика: создаёт новые задачи в `ПланЗаготовок` для перевыпуска компонентов бракованного изделия, возвращает заказ в статус `'в_работе'`. Результат: строка со статусом и сообщением.

### 12. Функция `sp_search_orders(p_user_id INTEGER, p_search_text VARCHAR, p_status VARCHAR, p_date_from DATE, p_date_to DATE)`
Функция выполняет поиск и фильтрацию заказов. Входные параметры: `p_user_id INTEGER` — id менеджера (или NULL для всех), `p_search_text VARCHAR` — текст поиска по ФИО клиента/id заказа, `p_status VARCHAR` — фильтр по статусу, `p_date_from DATE` и `p_date_to DATE` — диапазон дат. Логика: выполняет SELECT с JOIN на `Клиент` и `Сотрудник`, применяя все переданные фильтры. Результат: таблица заказов с id, ФИО клиента, ФИО менеджера, датами, статусом и суммой.

## II. CRUD-функции: Клиенты

### 13. Функция `sp_get_clients()`
Функция возвращает список всех клиентов. Входные параметры: отсутствуют. Логика: SELECT из таблицы `Клиент` с сортировкой по ФИО. Результат: таблица с полями: id_клиента, фио, номер_телефона, адрес, дата_регистрации, инн.

### 14. Функция `sp_search_clients(p_query VARCHAR)`
Функция ищет клиентов по текстовому запросу. Входные параметры: `p_query VARCHAR` — строка поиска. Логика: SELECT из `Клиент` с фильтром ILIKE по ФИО, телефону и адресу. Результат: таблица клиентов, совпадающих с запросом.

### 15. Функция `sp_save_client(p_id INTEGER, p_fio VARCHAR, p_phone VARCHAR, p_inn INTEGER, p_address TEXT)`
Функция создаёт или обновляет клиента. Входные параметры: `p_id INTEGER` — id клиента (NULL для создания нового), `p_fio VARCHAR` — ФИО, `p_phone VARCHAR` — телефон, `p_inn INTEGER` — ИНН, `p_address TEXT` — адрес. Логика: если `p_id IS NULL`, выполняет INSERT в таблицу `Клиент`. Иначе — UPDATE существующей записи. Результат: строка со статусом и сообщением.

### 16. Функция `sp_delete_client(p_client_id INTEGER)`
Функция удаляет клиента. Входные параметры: `p_client_id INTEGER` — id клиента. Логика: проверяет наличие связанных заказов. Если заказы есть — возвращает ошибку. Иначе — выполняет DELETE. Результат: строка со статусом и сообщением.

## III. CRUD-функции: Номенклатура (Изделия)

### 17. Функция `sp_get_products()`
Функция возвращает список всех изделий. Входные параметры: отсутствуют. Логика: SELECT из таблицы `Изделие` с сортировкой по наименованию. Результат: таблица с полями: id_изделия, наименование, тип, размеры, стоимость, количество_на_складе.

### 18. Функция `sp_create_product(p_name VARCHAR, p_type VARCHAR, p_size VARCHAR, p_price NUMERIC)`
Функция создаёт новое изделие. Входные параметры: `p_name VARCHAR` — наименование, `p_type VARCHAR` — тип, `p_size VARCHAR` — размеры, `p_price NUMERIC` — стоимость. Логика: INSERT в таблицу `Изделие` с `количество_на_складе = 0`. Результат: строка со статусом, сообщением и id созданного изделия.

### 19. Функция `sp_update_product(p_id INTEGER, p_name VARCHAR, p_type VARCHAR, p_size VARCHAR, p_price NUMERIC)`
Функция обновляет данные изделия. Входные параметры: `p_id INTEGER` — id изделия, `p_name VARCHAR` — новое наименование, `p_type VARCHAR` — новый тип, `p_size VARCHAR` — новые размеры, `p_price NUMERIC` — новая стоимость. Логика: UPDATE записи в `Изделие`. Результат: строка со статусом и сообщением.

### 20. Функция `sp_delete_product(p_product_id INTEGER)`
Функция удаляет изделие. Входные параметры: `p_product_id INTEGER` — id изделия. Логика: CASCADE DELETE через FK. Результат: строка со статусом и сообщением.

### 21. Функция `sp_get_product_components(p_product_id INTEGER)`
Функция возвращает состав изделия (список заготовок). Входные параметры: `p_product_id INTEGER` — id изделия. Логика: SELECT из `СоставИзделия` JOIN `Заготовка`. Результат: таблица с полями: id_заготовки, наименование, количество.

### 22. Функция `sp_add_product_component(p_prod_id INTEGER, p_comp_id INTEGER, p_qty INTEGER)`
Функция добавляет заготовку в состав изделия. Входные параметры: `p_prod_id INTEGER` — id изделия, `p_comp_id INTEGER` — id заготовки, `p_qty INTEGER` — количество. Логика: INSERT в `СоставИзделия`. Результат: строка со статусом и сообщением.

### 23. Функция `sp_update_product_component(p_prod_id INTEGER, p_comp_id INTEGER, p_qty INTEGER)`
Функция обновляет количество заготовки в составе изделия. Входные параметры: `p_prod_id INTEGER` — id изделия, `p_comp_id INTEGER` — id заготовки, `p_qty INTEGER` — новое количество. Логика: UPDATE `СоставИзделия`. Результат: строка со статусом и сообщением.

### 24. Функция `sp_delete_product_component(p_prod_id INTEGER, p_comp_id INTEGER)`
Функция удаляет заготовку из состава изделия. Входные параметры: `p_prod_id INTEGER` — id изделия, `p_comp_id INTEGER` — id заготовки. Логика: DELETE из `СоставИзделия`. Результат: строка со статусом и сообщением.

### 25. Функция `sp_get_product_components_status(p_order_id INTEGER, p_product_id INTEGER)`
Функция возвращает статус производства компонентов изделия для конкретного заказа. Входные параметры: `p_order_id INTEGER` — id заказа, `p_product_id INTEGER` — id изделия. Логика: для каждой заготовки из `СоставИзделия` вычисляет требуемое количество, суммирует фактическое из `ПланЗаготовок`, рассчитывает остаток. Результат: таблица с полями: наименование_заготовки, требуется, выполнено, осталось.

## IV. CRUD-функции: Заготовки

### 26. Функция `sp_get_all_components()`
Функция возвращает полный список заготовок. Входные параметры: отсутствуют. Логика: SELECT из `Заготовка`. Результат: таблица с полями: id_заготовки, наименование, количество_на_складе (количество_готовых).

### 27. Функция `sp_get_components()`
Функция возвращает краткий список заготовок. Входные параметры: отсутствуют. Логика: SELECT из `Заготовка`. Результат: таблица с полями: id_заготовки, наименование, количество_готовых.

### 28. Функция `sp_create_component(p_name VARCHAR)`
Функция создаёт новую заготовку. Входные параметры: `p_name VARCHAR` — наименование. Логика: INSERT в `Заготовка` с `количество_готовых = 0`. Результат: строка со статусом, сообщением и id созданной заготовки.

### 29. Функция `sp_update_component(p_id INTEGER, p_name VARCHAR)`
Функция обновляет наименование заготовки. Входные параметры: `p_id INTEGER` — id заготовки, `p_name VARCHAR` — новое наименование. Логика: UPDATE `Заготовка`. Результат: строка со статусом и сообщением.

### 30. Функция `sp_delete_component(p_component_id INTEGER)`
Функция удаляет заготовку. Входные параметры: `p_component_id INTEGER` — id заготовки. Логика: CASCADE DELETE. Результат: строка со статусом и сообщением.

### 31. Функция `sp_get_component_materials(p_comp_id INTEGER)`
Функция возвращает список материалов, необходимых для заготовки. Входные параметры: `p_comp_id INTEGER` — id заготовки. Логика: SELECT из `РасходМатериалов` JOIN `Материал`. Результат: таблица с полями: id_материала, наименование, количество.

### 32. Функция `sp_add_component_material(p_comp_id INTEGER, p_mat_id INTEGER, p_qty INTEGER)`
Функция добавляет материал в рецептуру заготовки. Входные параметры: `p_comp_id INTEGER` — id заготовки, `p_mat_id INTEGER` — id материала, `p_qty INTEGER` — количество. Логика: INSERT в `РасходМатериалов` (таблица `СоставЗаготовки`). Результат: строка со статусом и сообщением.

### 33. Функция `sp_update_component_material(p_comp_id INTEGER, p_mat_id INTEGER, p_qty INTEGER)`
Функция обновляет количество материала в рецептуре заготовки. Входные параметры: `p_comp_id INTEGER` — id заготовки, `p_mat_id INTEGER` — id материала, `p_qty INTEGER` — новое количество. Логика: UPDATE `РасходМатериалов`. Результат: строка со статусом и сообщением.

### 34. Функция `sp_delete_component_material(p_comp_id INTEGER, p_mat_id INTEGER)`
Функция удаляет материал из рецептуры заготовки. Входные параметры: `p_comp_id INTEGER` — id заготовки, `p_mat_id INTEGER` — id материала. Логика: DELETE из `РасходМатериалов`. Результат: строка со статусом и сообщением.

## VI. Функции производства

### 38. Функция `sp_get_production_plan_full()`
Функция возвращает полный план производства. Входные параметры: отсутствуют. Логика: SELECT из `ПланЗаготовок` с JOIN на `Заготовка` и `Сотрудник`, сортировка по статусу (в_работе → назначено → принято → выполнено → отменено) и дате плана. Результат: таблица с полями: id_заготовки, id_заказа, заготовка (наименование), плановое_количество, фактическое_количество, дедлайн, дата_фактическая, статус, сборщик (ФИО), id_сотрудника.

### 39. Функция `sp_get_assembler_tasks()`
Функция возвращает список задач для сборщика. Входные параметры: отсутствуют. Логика: SELECT из `ПланЗаготовок` JOIN `Заготовка`, возвращая все задачи с сортировкой по дате плана. Результат: таблица с полями: тип_задачи ('заготовка'), id_объекта, id_заказа, наименование_задачи, плановое_количество, фактическое_количество, дедлайн, статус, id_сборщика.

### 40. Функция `sp_get_order_tasks(p_order_id INTEGER)`
Функция возвращает задачи для конкретного заказа. Входные параметры: `p_order_id INTEGER` — id заказа. Логика: SELECT из `ПланЗаготовок` JOIN `Заготовка` WHERE id_заказа = p_order_id. Результат: таблица с полями: тип_задачи, наименование, плановое_количество, статус, дедлайн.

### 41. Функция `sp_get_order_items(p_order_id INTEGER)`
Функция возвращает состав заказа (список изделий). Входные параметры: `p_order_id INTEGER` — id заказа. Логика: SELECT из `СоставЗаказа` JOIN `Изделие`, вычисляя сумму как количество × стоимость. Результат: таблица с полями: id_изделия, наименование, количество, цена, сумма.

### 42. Функция `sp_get_employees()`
Функция возвращает список всех сотрудников. Входные параметры: отсутствуют. Логика: SELECT из `Сотрудник`. Результат: таблица с полями: id_сотрудника, фио, должность, login, дата_увольнения, номер_телефона, зарплата.

### 43. Функция `sp_get_workers()`
Функция возвращает список активных сборщиков. Входные параметры: отсутствуют. Логика: SELECT из `Сотрудник` WHERE `дата_увольнения IS NULL` AND `должность = 'сборщик'`. Результат: таблица с полями: id_сотрудника, фио, должность.

### 44. Функция `sp_hire_employee(p_fio VARCHAR, p_phone VARCHAR, p_birth_date DATE, p_role VARCHAR, p_salary NUMERIC, p_login VARCHAR, p_password VARCHAR)`

### 45. Функция `sp_get_schedule(p_employee_id INTEGER)`
Функция возвращает расписание сотрудника. Входные параметры: `p_employee_id INTEGER` — id сотрудника. Логика: SELECT из `Расписание` для указанного сотрудника. Результат: таблица с датами и статусами рабочих дней.

### 46. Процедура `sp_set_day_status(p_employee_id INTEGER, p_date DATE, p_status VARCHAR)`
Процедура устанавливает статус дня в расписании сотрудника. Входные параметры: `p_employee_id INTEGER` — id сотрудника, `p_date DATE` — дата, `p_status VARCHAR` — статус ('работа', 'выходной', 'отпуск', 'больничный'). Логика: INSERT или UPDATE в таблице `Расписание` (UPSERT). Результат: запись расписания обновлена.

### 51. Функция `sp_get_dashboard_summary(p_start DATE, p_end DATE)`
Функция возвращает сводную статистику за период. Входные параметры: `p_start DATE` — начало периода, `p_end DATE` — конец периода. ### 54. Функция `sp_get_profit_chart_data(p_start DATE, p_end DATE)`
Функция возвращает данные для графика прибыли. Входные параметры: `p_start DATE`, `p_end DATE` — период. Логика: вычисляет разницу продаж и расходов по дням. Результат: таблица с полями: d (дата), val (прибыль).

### 55. Функция `sp_get_orders_count_chart_data(p_start DATE, p_end DATE)`
Функция возвращает данные для графика количества заказов. Входные параметры: `p_start DATE`, `p_end DATE` — период. Логика: COUNT заказов по дням. Результат: таблица с полями: d (дата), val (количество).

## XII. Триггерные функции и триггеры

### 60. Функция `trg_check_age_func()` и триггер `trg_check_age` на таблицу `Сотрудник`
Функция и триггер проверяют совершеннолетие сотрудника при добавлении или обновлении. Входные параметры: (триггерная) NEW запись для таблицы `Сотрудник`. Логика: при INSERT или UPDATE вычисляется возраст по полю `дата_рождения`, если возраст меньше 18 лет, выбрасывается исключение с сообщением «Сотрудник должен быть совершеннолетним». Результат: предотвращается добавление или обновление записи сотрудника младше 18 лет.

### 61. Функция `sp_check_order_ready()` и триггер `tr_check_order_ready` на таблицу `ПланЗаготовок`
Триггерная функция автоматически завершает заказ при выполнении всех задач. Входные параметры: (триггерная) NEW запись при обновлении статуса. Логика: срабатывает AFTER UPDATE OF статус на `ПланЗаготовок`, когда `NEW.статус = 'выполнено'`. Считает количество незавершённых задач для заказа. Если все задачи выполнены — устанавливает `статус = 'завершен'` и `дата_готовности = CURRENT_DATE` в таблице `Заказ`. Результат: заказ автоматически завершается при выполнении всех задач.

### 62. Функция `sp_calculate_order_sum()` и триггер `tr_order_sum_update` на таблицу `СоставЗаказа`
Триггерная функция автоматически пересчитывает сумму заказа. Входные параметры: (триггерная) NEW/OLD записи `СоставЗаказа`. Логика: срабатывает AFTER INSERT, UPDATE, DELETE на `СоставЗаказа`. Пересчитывает `сумма_заказа` в таблице `Заказ` как SUM(`количество_изделий * цена_фиксированная`). Результат: сумма заказа всегда актуальна.

### 63. Функция `fn_check_order_completion()` и триггер `trg_order_completion` на таблицу `ПланЗаготовок`
Триггерная функция проверяет завершение всех задач заказа. Входные параметры: (триггерная) NEW/OLD записи `ПланЗаготовок`. Логика: срабатывает AFTER UPDATE на `ПланЗаготовок`. Проверяет, остались ли незавершённые задачи для заказа. Если все выполнены — обновляет статус заказа. Результат: автоматическое отслеживание готовности заказа.

### 64. Функция `fn_update_task_date_fact()` и триггер `trg_task_date_fact` на таблицу `ПланЗаготовок`
Триггерная функция автоматически устанавливает дату фактического выполнения. Входные параметры: (триггерная) NEW запись `ПланЗаготовок`. Логика: срабатывает BEFORE UPDATE на `ПланЗаготовок`. Если `фактическое_количество` изменилось — устанавливает `дата_факт = CURRENT_TIMESTAMP`. Результат: дата фактического выполнения обновляется автоматически.
